# 비밀번호 찾기(재설정) 설정 가이드

사용자앱·판매자앱의 **비밀번호 찾기**를 켜기 위해 **한 번만** 해두면 되는 Supabase 콘솔 설정입니다.
개발 지식이 없어도 아래 순서대로 그대로 따라 하면 됩니다. (예상 소요: 40~60분, 대부분 SMTP 준비 시간)

FoodPicker 의 비밀번호 재설정은 **메일로 6자리 숫자 코드를 보내는 방식**입니다.
메일 안의 링크를 누르는 방식이 아닙니다.

```
① 앱에서 이메일 입력  →  Supabase 가 [푸드피커] 비밀번호 재설정 인증코드 메일 발송
② 사용자가 메일에서 6자리 숫자를 읽어 앱에 입력  (PC 메일함에서 읽어도 됩니다)
③ 앱이 새 비밀번호를 저장  →  로그아웃  →  새 비밀번호로 로그인
```

> 📌 왜 링크가 아니라 6자리 코드인가요?
> - **Expo Go 에서도 동작합니다.** `foodpicker://` 같은 앱 전용 주소(커스텀 스킴)를 쓰지 않기 때문입니다.
>   (간편 로그인은 이 제약 때문에 dev build 가 필요합니다 — `SOCIAL_LOGIN_SETUP.md` 참고)
> - **메일을 PC 에서 열어도 됩니다.** 링크 방식은 사용자앱 구조상 "요청한 그 폰에서 그 앱으로" 열어야만 동작합니다.
> - **Redirect URLs 설정 실수로 인한 사고가 원천 차단됩니다.**

## ✅ 현재 적용 상태 (2026-08-06 확인)

아래 항목은 **이미 적용을 마쳤습니다.** 다시 하실 필요가 없고, 이 문서의 나머지는
값이 바뀌었을 때 참고하시라고 남겨둔 것입니다.

| 항목 | 위치 | 적용된 값 |
|---|---|---|
| 커스텀 SMTP | Authentication → Emails → SMTP Settings | **ON** |
| 발신 주소 / 이름 | 〃 | `foodpicker77@gmail.com` / `FoodPicker` |
| SMTP 호스트 / 포트 | 〃 | `smtp.gmail.com` / `465` |
| SMTP 사용자 / 비밀번호 | 〃 | `foodpicker77@gmail.com` / 등록 완료(Gmail 앱 비밀번호) |
| 재설정 메일 제목 | Authentication → Emails → Templates → Reset password | `[푸드피커] 비밀번호 재설정 인증코드` |
| 재설정 메일 본문 | 〃 | 한국어 + `{{ .Token }}`, `{{ .ConfirmationURL }}` **제거 완료** |
| 인증코드 길이 | Authentication → Sign In / Providers → Email | **6자리** (기존 8자리 → 앱과 불일치라 교정) |
| 인증코드 만료 | 〃 | `3600`초 (1시간) |
| 최소 비밀번호 길이 | 〃 | `6`자 (앱 검증과 동일) |

> ⚠️ **인증코드 길이는 반드시 6이어야 합니다.**
> 앱의 입력칸이 6자리로 고정돼 있어(`OTP_LENGTH = 6`) 콘솔 값이 8이면 사용자가 8자리 코드를
> 다 입력할 수 없어 **인증이 100% 실패합니다.** 실제로 8로 설정돼 있던 것을 6으로 바꿨습니다.
> 이 값을 다시 바꾸실 때는 앱의 `src/lib/auth.js` 의 `OTP_LENGTH` 도 함께 바꿔야 합니다.

### Gmail SMTP 로 운영할 때 알아둘 점

Supabase 콘솔이 SMTP 화면에서 이런 경고를 띄웁니다 — 잘못된 설정이라는 뜻은 아닙니다.

> "It looks like the SMTP provider you entered is designed for sending personal
> rather than transactional email messages. Email deliverability may be impacted."

Gmail 은 원래 개인용 메일 서비스라 **대량 발송에 최적화돼 있지 않습니다.** 실제 제약은 이렇습니다.

- **일일 발송 한도**가 있습니다(무료 Gmail 기준 대략 500통/일). 사용자가 늘면 한도에 걸려
  그날 이후 재설정 메일이 **조용히 발송되지 않습니다.**
- 네이버·다음 등 국내 메일에서 **스팸함으로 분류될 확률이 상대적으로 높습니다.**
  자체 도메인(예: `no-reply@foodpicker.app`) + SPF/DKIM 을 쓰는 전용 발송 서비스보다 불리합니다.
- 발신 주소를 Gmail 계정과 다르게 지정하면 Gmail 이 다시 써버립니다. 지금처럼
  발신 주소와 SMTP 사용자를 같게(`foodpicker77@gmail.com`) 두어야 합니다.

**지금 단계(개발·시연·초기 운영)에서는 이대로 충분합니다.** 정식 오픈 후 사용자가 늘면
아래 ①의 Resend/SendGrid 같은 전용 발송 서비스로 옮기시길 권합니다. 옮길 때 바꿀 것은
SMTP 4개 값(호스트·포트·사용자·비밀번호)뿐이고 앱 코드는 그대로입니다.

### 🔐 Gmail 앱 비밀번호 관리

앱 비밀번호는 **Gmail 계정 비밀번호와 별개로 발급되는 16자리 값**이고, 유출되면 그 계정으로
메일을 보낼 수 있습니다. 다음 두 가지만 지켜주세요.

- 앱 비밀번호를 **메신저·메일·문서에 남기지 마세요.** 이미 어딘가에 공유하셨다면
  [Google 계정 → 보안 → 앱 비밀번호](https://myaccount.google.com/apppasswords)에서
  **기존 값을 삭제하고 새로 발급**한 뒤, 위 SMTP 설정의 비밀번호만 교체하시면 됩니다.
- 앱 비밀번호는 **2단계 인증이 켜져 있어야** 발급됩니다. 2단계 인증을 끄면 기존 앱 비밀번호도
  함께 무효화되어 메일 발송이 멈춥니다.

## ⓞ 이 설정이 없으면 어떻게 되나요

| 안 한 설정 | 실제 증상 |
| --- | --- |
| ① 커스텀 SMTP | **실제 사용자에게 메일이 아예 도착하지 않습니다.** 앱은 "메일을 보냈습니다" 라고 정상 안내합니다 |
| ② 메일 템플릿 | 영어로 된 메일이 오고, **6자리 코드가 본문에 없습니다.** 사용자가 입력할 값이 없습니다 |
| ③ OTP 만료 시간 | 코드가 1시간이나 유효합니다(기본값). 메일 문구와 숫자가 어긋납니다 |
| ④ 레이트리밋 | 하루 몇 건만 발송되고 나머지는 조용히 실패합니다 |

**①과 ②는 필수입니다.** 둘 중 하나라도 빠지면 기능이 동작하지 않습니다.

## ① 커스텀 SMTP 설정 (필수, 30분)

### ①-1 왜 반드시 해야 하나요

Supabase 는 아무 설정도 하지 않으면 **내장(기본) SMTP** 로 메일을 보냅니다. 이 내장 SMTP 는
**테스트 전용**이라 다음 두 가지 제약이 있습니다.

1. **시간당 발송량이 극히 적습니다** (수 건 수준). 실사용자 문의가 몰리면 대부분 실패합니다.
2. **Supabase 조직에 초대된 팀 멤버의 이메일 주소로만 발송됩니다.**
   → 일반 사용자가 "비밀번호 찾기" 를 눌러도 **메일이 오지 않습니다.**
   앱은 계정 열거(어떤 이메일이 가입돼 있는지 캐내는 공격)를 막기 위해
   성공/실패와 무관하게 항상 "메일을 보냈습니다" 라고 안내하므로, **화면만 보고는 실패를 알 수 없습니다.**

즉 커스텀 SMTP 전환은 이 기능의 **사실상 전제조건**입니다.

### ①-2 미리 준비할 것

| 준비물 | 설명 |
| --- | --- |
| 발신 도메인 | 예: `foodpicker.app`. 없으면 도메인을 먼저 구입해야 합니다(연 2만원 내외) |
| SMTP 제공자 계정 | Resend / SendGrid / AWS SES / Mailgun 중 하나. **Resend 가 가장 간단**합니다(무료 하루 100통) |
| DNS 접근 권한 | 도메인을 산 곳(가비아·후이즈·Cloudflare 등)의 DNS 관리 화면 |

> ⚠️ **네이버·다음 메일 대응** — 발신 도메인의 DNS 에 **SPF · DKIM** 레코드를 반드시 등록하세요.
> 등록하지 않으면 메일이 도착은 하지만 **스팸함으로 분류**됩니다.
> 국내 메일 서비스는 특히 엄격해서, "메일이 안 와요" 문의의 대부분이 이 원인입니다.
> SPF/DKIM 레코드 값은 SMTP 제공자가 가입 직후 화면에 그대로 보여줍니다 — 복사해서 DNS 에 붙여넣으면 됩니다.

### ①-3 Resend 기준 절차 (다른 제공자도 흐름은 같습니다)

1. https://resend.com 접속 → 가입.
2. 왼쪽 메뉴 **Domains** → **Add Domain** → 소유한 도메인(예: `foodpicker.app`) 입력.
3. 화면에 나오는 **DNS 레코드 3~4개**(SPF/DKIM/DMARC)를 도메인 관리 사이트의 DNS 설정에 그대로 추가합니다.
4. Resend 화면에서 **Verify** 를 눌러 초록색 `Verified` 가 될 때까지 기다립니다. (보통 10분~1시간)
5. 왼쪽 메뉴 **API Keys** → **Create API Key** → 생성된 키를 복사해 메모합니다.
   - ⚠️ 이 키는 **생성 직후 한 번만** 보입니다. 창을 닫기 전에 반드시 복사하세요.

### ①-4 Supabase 에 붙여넣기

1. Supabase 대시보드 → **Project Settings** → **Authentication** → **SMTP Settings**
   (버전에 따라 **Authentication → Emails → SMTP Settings**).
2. **Enable Custom SMTP** 토글을 **켭니다**.
3. 아래 값을 채웁니다. (Resend 기준)

| 항목 | 값 |
| --- | --- |
| Sender email | `no-reply@foodpicker.app` (①-2 에서 인증한 도메인이어야 합니다) |
| Sender name | `푸드피커` |
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | ①-3 에서 복사한 **API Key** |

4. **Save** 를 누릅니다.

> 다른 제공자를 쓴다면 Host/Port/Username 만 다릅니다. 제공자 문서의 "SMTP" 항목을 그대로 옮기세요.
> **Sender email 의 도메인은 반드시 ①-2 에서 인증한 도메인이어야 합니다.** 아무 주소나 넣으면 전량 반송됩니다.

## ② 재설정 메일 템플릿 한국어화 (필수, 5분)

**이 단계를 건너뛰면 사용자가 입력할 6자리 코드가 메일에 없습니다.** 기본 템플릿에는 링크만 있습니다.

1. Supabase 대시보드 → **Authentication** → **Emails** → **Templates** 탭.
2. 목록에서 **"Reset Password"** 를 선택합니다. (Confirm signup / Magic Link 가 아닙니다)
3. **Subject** 를 아래로 바꿉니다.

```
[푸드피커] 비밀번호 재설정 인증코드
```

4. **Message body** 를 **전부 지우고** 아래를 그대로 붙여넣습니다.

```html
<h2>비밀번호 재설정</h2>
<p>안녕하세요, 푸드피커입니다.</p>
<p>아래 <b>6자리 인증코드</b>를 앱 화면에 입력해주세요.</p>
<p style="font-size:32px; font-weight:bold; letter-spacing:8px; margin:24px 0;">{{ .Token }}</p>
<p>이 코드는 <b>10분간</b> 유효합니다.</p>
<p style="color:#888; font-size:13px;">
  본인이 요청하지 않았다면 이 메일을 무시하셔도 됩니다. 비밀번호는 변경되지 않습니다.
</p>
```

5. **Save** 를 누릅니다.

### ★ `{{ .ConfirmationURL }}` 은 반드시 지워야 합니다

기본 템플릿에 들어 있는 `{{ .ConfirmationURL }}` (파란색 링크)을 **남겨두면 안 됩니다.**

- 사용자는 코드를 타이핑하는 대신 **눈앞의 링크를 누릅니다.**
- 링크를 누르면 앱이 열리면서 **앱의 딥링크 처리기가 그 인증을 "그냥 로그인" 으로 소비해 버립니다.**
  → 새 비밀번호를 입력할 화면이 뜨지 않고 그냥 로그인된 상태가 됩니다.
- 이 인증은 **1회용**이라, 그 뒤에 앱에서 코드를 입력해도 이미 사용된 값이라 실패합니다.

즉 링크를 남기면 **"눌렀더니 그냥 로그인되고 비밀번호는 그대로"** 라는 가장 나쁜 증상이 나옵니다.
위 4번의 HTML 에는 링크가 없으니, **통째로 교체**하면 안전합니다.

> 📌 사용자앱과 판매자앱은 **같은 Supabase 프로젝트**를 공유하므로 템플릿은 하나뿐입니다.
> 그래서 문구를 "푸드피커" 로 앱 중립적으로 씁니다. "판매자님" 같은 표현을 넣으면 구매자에게도 그대로 갑니다.

## ③ 인증코드 길이·만료 시간 (필수, 2분)

1. Supabase 대시보드 → **Authentication** → **Emails**
   (버전에 따라 **Authentication → Sign In / Providers → Email**).
2. 아래 두 값을 확인·수정합니다.

| 항목 | 설정할 값 | 이유 |
| --- | --- | --- |
| **Email OTP Length** | `6` (기본값) | 앱 화면이 6칸 입력을 전제로 만들어져 있습니다. 바꾸지 마세요 |
| **Email OTP Expiration** | `600` 초 (= 10분) | 기본값은 `3600`(1시간)이라 너무 깁니다 |

3. **Save**.

> ⚠️ ②의 메일 문구("이 코드는 **10분간** 유효합니다")와 여기의 숫자를 **반드시 일치**시키세요.
> 한쪽만 바꾸면 "10분이라더니 5분 만에 만료됐다" 같은 문의가 들어옵니다.

## ④ 메일 발송 한도(Rate Limits) 확인 (필수, 2분)

1. Supabase 대시보드 → **Authentication** → **Rate Limits**.
2. **"Rate limit for sending emails"** (시간당 발송 건수) 값을 확인하고 필요하면 올립니다.
   - ⚠️ **① 커스텀 SMTP 를 켠 뒤에만** 의미 있는 상향이 가능합니다. 내장 SMTP 상태에서 숫자만 올려도 소용없습니다.
   - 초기 운영 기준 시간당 `100` 정도면 충분합니다.
3. **Save**.

### 같은 이메일에 대한 60초 재요청 제한

Supabase 는 **같은 이메일 주소로의 재발송을 60초 간격으로 제한**합니다. 이건 설정으로 끌 수 없습니다.
그래서 두 앱의 "인증코드 다시 받기" 버튼은 **60초 쿨다운 타이머**를 두고 있습니다.
사용자가 60초 안에 다시 누르면 앱이 "잠시 후 다시 요청해주세요" 라고 안내합니다 — 정상 동작입니다.

## ⑤ Providers → Email 의 현재 값 점검 (5분)

**Authentication → Sign In / Providers → Email** 을 열어 아래 네 가지를 확인합니다.

| 항목 | 확인 내용 |
| --- | --- |
| **Minimum password length** | 두 앱 모두 **6자 이상**으로 검증합니다. 콘솔 값이 6보다 크면 앱은 통과시키는데 서버가 거절해 "알 수 없는 오류" 가 납니다. **6으로 맞추거나** 앱 검증 기준을 콘솔 값에 맞춰 올려야 합니다 |
| **Secure password change** | 켜져 있으면 *로그인 상태에서의* 비밀번호 변경 화면이 현재 비밀번호 재확인을 요구합니다(앱은 이미 그렇게 만들어져 있습니다). **비밀번호 찾기(재설정) 흐름은 이 제약의 예외**이므로 영향 없습니다 |
| **Confirm email** | 켜져 있으면 **가입 후 메일 인증을 하지 않은 계정**은 재설정 메일을 받지 못할 수 있습니다. 앱은 이 경우에도 "메일을 보냈습니다" 로만 안내합니다(계정 열거 방지) |
| **Prevent use of leaked passwords** | 켜면 유출 이력이 있는 비밀번호가 거절됩니다. 앱에는 이 경우의 전용 안내 문구가 없어 일반 오류로 표시됩니다 |

## ⑥ (보완) Redirect URLs 에 판매자앱 주소 추가

**비밀번호 찾기에는 필요 없지만**, 점검하는 김에 함께 고쳐두시길 권합니다.

`SOCIAL_LOGIN_SETUP.md` **①절**은 Redirect URLs 에 **사용자앱 주소 두 개만** 등록하도록 안내하고 있습니다.

```
foodpicker://auth-callback
foodpicker://**
```

그런데 **판매자앱 회원가입 인증 메일도 같은 허용목록을 사용**합니다(판매자앱은 `foodpicker-seller://auth-callback` 을 쓴다).
이 주소가 목록에 없으면 판매자 가입 인증 메일의 링크가 **앱을 열지 못하고 조용히 Site URL(웹 페이지)로 튑니다.**
에러가 나지 않고 "링크를 눌렀는데 앱이 안 열리고 웹페이지가 뜬다" 는 증상으로만 나타나서 원인을 찾기 어렵습니다.

1. Supabase 대시보드 → **Authentication** → **URL Configuration**.
2. **Redirect URLs** 에 **Add URL** 로 아래 두 개를 추가합니다.

```
foodpicker-seller://auth-callback
foodpicker-seller://**
```

3. **Save**.

> 비밀번호 재설정은 6자리 코드 방식이라 **Redirect URLs 와 무관**합니다.
> 위 추가는 판매자앱 **가입 인증 메일**을 위한 것입니다.

## ⑦ 동작 확인 체크리스트

1. **본인 이메일로 가입한 테스트 계정**을 하나 준비합니다. (팀 멤버 주소가 아닌 일반 주소로 — SMTP 검증이 목적입니다)
2. 앱 로그인 화면 → **"비밀번호 찾기"** → 이메일 입력 → **[인증코드 받기]**.
3. **1분 안에 메일이 도착**하는지 확인합니다.
   - 안 오면 **스팸함**을 먼저 확인하세요. 스팸함에 있다면 ①-2 의 SPF/DKIM 문제입니다.
4. 메일 제목이 **`[푸드피커] 비밀번호 재설정 인증코드`** 이고 본문에 **6자리 숫자**가 보이는지 확인합니다.
   - 영어 메일이 오거나 숫자가 없으면 **② 템플릿이 저장되지 않은 것**입니다.
   - 본문에 **파란 링크가 있으면 ②를 다시 하세요** — `{{ .ConfirmationURL }}` 이 남아 있습니다.
5. 앱에 6자리를 입력하고 새 비밀번호(6자 이상)를 두 번 입력 → **[비밀번호 변경]**.
6. "비밀번호가 변경되었습니다" 안내 후 **로그인 화면으로 되돌아오는지** 확인합니다.
7. **새 비밀번호로 로그인**되는지, **이전 비밀번호로는 로그인이 안 되는지** 확인합니다.
8. 사용자앱·판매자앱 **양쪽 모두** 3~7번을 반복합니다. (같은 Supabase 프로젝트라 설정은 공유되지만 화면은 각각입니다)

## ⑧ 자주 나는 오류와 원인

| 증상 | 원인 / 해결 |
| --- | --- |
| 메일이 아예 안 온다 (스팸함에도 없다) | 커스텀 SMTP 미설정 → **①**. 내장 SMTP 는 팀 멤버 주소로만 발송됩니다 |
| 메일이 스팸함에 들어간다 | 발신 도메인의 SPF/DKIM 미등록 → **①-2 / ①-3 3번** |
| 메일은 오는데 영어다 | Reset Password 템플릿 미수정 → **②** (Confirm signup 템플릿을 고친 건 아닌지 확인) |
| 메일에 6자리 숫자가 없다 | 템플릿에 `{{ .Token }}` 누락 → **②-4** |
| 링크를 눌렀더니 그냥 로그인되고 비밀번호는 안 바뀐다 | 템플릿에 `{{ .ConfirmationURL }}` 이 남아 있음 → **②의 ★ 절** |
| 인증코드가 만료되었거나 올바르지 않습니다 | 코드 오타 / 10분 초과 / **이미 한 번 사용한 코드**. 새로 받아야 합니다 |
| 잠시 후 다시 요청해주세요 | 같은 이메일 60초 재요청 제한 → **④**. 정상 동작입니다 |
| 메일 발송 한도를 초과했습니다 | 시간당 발송 한도 초과 → **④** (또는 내장 SMTP 사용 중) |
| 비밀번호는 6자 이상이어야 합니다 (6자를 넣었는데도) | 콘솔의 Minimum password length 가 6보다 큼 → **⑤** |
| 비밀번호를 바꿨는데 심사중 화면에 갇힌다 (판매자앱) | 정상 흐름이 아닙니다. 재설정 완료 후에는 자동 로그아웃되어야 합니다 — 앱 버전을 확인하세요 |
| 판매자 가입 인증 메일 링크가 앱을 안 연다 | Redirect URLs 에 판매자앱 스킴 누락 → **⑥** |

## ⑨ 소셜(카카오·구글·네이버) 로 가입한 계정은?

사용자앱에만 해당합니다. (판매자앱은 이메일 로그인 전용이라 무관합니다)

- 소셜로만 가입한 계정은 **비밀번호가 아예 없습니다.** 그래도 비밀번호 찾기는 동작합니다 —
  재설정을 마치면 **비밀번호가 새로 만들어져** 이후 이메일 로그인도 가능해집니다.
- 앱은 인증코드 확인 후 이 상황을 감지해
  *"지금까지 카카오/구글로 로그인해오셨어요. 비밀번호를 만들면 이메일로도 로그인할 수 있습니다"* 라고 안내합니다.
- **요청 단계에서 미리 "이 계정은 카카오 가입입니다" 라고 알려주지는 않습니다.**
  그렇게 하면 아무나 이메일을 넣어보며 가입 여부를 캐낼 수 있기 때문입니다(계정 열거).
- 더 간단한 우회로도 있습니다: **원래 쓰던 소셜 버튼으로 그냥 로그인**하면 됩니다.
